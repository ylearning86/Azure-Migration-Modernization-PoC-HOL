# 4.4. 移行アセスメント

Azure Migrate アプライアンスをオンプレ環境にセットアップし、移行元システムの検出・評価を行います。

> **Nested Hyper-V 版の特徴**: Hyper-V ホスト VM 自体をアプライアンスとして構成します。メイン版のように別途アプライアンス VM を作成する必要はありません。Hyper-V 検出シナリオにより、ゲスト VM（vm-ad01 / vm-app01 / vm-sql01）が自動的に検出されます。

## 目的

- Azure Migrate アプライアンスを Hyper-V ホスト上にセットアップする
- 移行元サーバー（vm-ad01 / vm-app01 / vm-sql01）を Hyper-V 検出で検出する
- Azure VM / Azure SQL / App Service への適合性を評価する
- 評価結果をもとに Spoke1〜4 のどの移行パターンが適切か判断する

## 対象

| サーバー | 主な評価観点 |
| --- | --- |
| `vm-app01` | Azure VM / App Service / コンテナ化適性 |
| `vm-sql01` | SQL Server → Azure SQL の適性 |
| `vm-ad01` | 基盤系として残置または接続継続の検討 |

## 前提条件

- Nested Hyper-V 疑似オンプレ環境がデプロイ済み（[architecture-nested-hyperv.md](../architecture/architecture-nested-hyperv.md) §4）
- Parts Unlimited のセットアップ済み（[1.3](./1.3-onprem-parts-unlimited.md)）
- VPN 接続済み（[architecture-nested-hyperv.md](../architecture/architecture-nested-hyperv.md) §5）

---

## Step 1: Azure Migrate プロジェクトの作成

1. Azure Portal で **Azure Migrate** を検索して開く
2. **[サーバー、データベース、Web アプリ]** を選択
3. **[プロジェクトの作成]** をクリック
4. 以下を入力:

   | 項目 | 値 |
   | --- | --- |
   | サブスクリプション | 使用中のサブスクリプション |
   | リソース グループ | `rg-hub` |
   | プロジェクト名 | `migr-project` |
   | 地域 | `東日本` |

5. **[作成]** をクリック

---

## Step 2: アプライアンスのセットアップ

Nested Hyper-V 環境では、**Hyper-V ホスト VM（vm-onprem-nested-hv01）自体をアプライアンスとして構成** します。別途 VM を作成する必要はありません。

### 2-1. Azure Migrate でキーを生成

1. Azure Portal の Azure Migrate プロジェクトで **[検出]** をクリック
2. **[マシンは仮想化されていますか？]** → **[はい、Hyper-V を使用]** を選択
3. **[アプライアンス名]** に `appliance01` と入力
4. **[キーの生成]** をクリックしてキーをコピー

### 2-2. インストーラーの実行

Bastion RDP でホスト VM（`vm-onprem-nested-hv01`）に接続し、管理者 PowerShell で実行:

```powershell
cd C:\AzureMigrateInstaller
.\AzureMigrateInstaller.ps1
```

対話プロンプトに以下の順で入力:
- `2`（Hyper-V）
- `1`（Azure Public）
- `1`（Public endpoint）
- `Y`（確認）

> **インストーラーの配置**: Portal からダウンロードした `.zip` を展開して `C:\AzureMigrateInstaller` に配置するか、ローカル PC から Blob Storage 経由で転送します。

### 2-3. 構成マネージャーでの登録

インストール完了後、Edge ブラウザで構成マネージャーを開く:

```powershell
start microsoft-edge:https://localhost:44368
```

1. 前提条件チェックが実行される（すべて緑になることを確認）
2. コピーしたプロジェクトキーを貼り付けて **[Verify]**
3. **[Login]** → デバイスコード認証で Azure アカウントにログイン
4. **[Successfully registered]** と表示されれば登録完了

---

## Step 3: 検出の構成

### 3-1. Hyper-V ホスト資格情報の追加（Step 1 on Configuration Manager）

| 項目 | 値 |
| --- | --- |
| Friendly name | `hypervadmin`（ハイフン不可） |
| Username | `labadmin` |
| Password | ホスト VM の管理者パスワード |

### 3-2. Hyper-V ホストの追加（Step 2 on Configuration Manager）

**[Add discovery source]** → **[Add single item]** を選択:

| 項目 | 値 |
| --- | --- |
| IP address / FQDN | `localhost` |
| Mapped credentials | `hypervadmin` |

**[Save]** → **Validation successful** を確認。

### 3-3. ゲスト VM 資格情報の追加（Step 3 on Configuration Manager — オプション）

ソフトウェアインベントリ・依存関係分析・SQL Server 検出を行う場合:

| 項目 | 値 |
| --- | --- |
| Credential type | **Domain Credential** |
| Friendly name | `contosoadmin` |
| Domain FQDN | `contoso.local` |
| Username | `Administrator` |
| Password | `P@ssW0rd1234!` |

> この資格情報は SQL Server インスタンスの検出にも自動的に使用されます。

### 3-4. 検出の開始

**[Start discovery]** をクリック。

検出されるまで 10〜15 分かかります。Azure Portal の **Azure Migrate** → **サーバー、データベース、Web アプリ** ダッシュボードで vm-ad01 / vm-app01 / vm-sql01 が表示されることを確認します。

<details>
<summary>Step 6: 評価結果の確認</summary>

Azure Portal の Azure Migrate ダッシュボードで、各評価の結果を確認します。

### 確認ポイント

| 評価 | 確認すべき内容 |
| --- | --- |
| Azure VM 評価 | 推奨サイズ、準備状況、月額コスト見積もり |
| Azure SQL 評価 | Azure SQL DB / Managed Instance の推奨、互換性の問題 |
| App Service 評価 | Web アプリの .NET バージョン互換性、移行可能性 |

### 結果を踏まえた移行パターンの選定

| パターン | 判断軸 | 評価結果の見どころ |
| --- | --- | --- |
| Rehost | とにかく早く移したい | VM 評価で推奨サイズとコストを確認 |
| DB PaaS 化 | DB だけ先行してモダナイズしたい | SQL 評価で互換性の問題が少ないか |
| コンテナ化 | DevOps / 移植性 / スケール重視 | App Service 評価で .NET バージョン確認 |
| フル PaaS 化 | 運用負荷を最小化したい | SQL + App Service 評価の両方を確認 |

</details>

<details>
<summary>トラブルシューティング</summary>

### AgentAuthenticationSpn エラー

検出開始後に `Source discovery failed` や `An unexpected error occurred on the appliance` と表示される場合、アプライアンスの SPN（Service Principal）設定が不完全な可能性があります。

**確認方法**（アプライアンス VM の管理者 PowerShell で実行）:

```powershell
# Discovery ログでエラーを確認
Get-Content "C:\ProgramData\Microsoft Azure\Logs\Server\Discovery\Service_*.log" -Tail 50
```

`An invalid parameter AgentAuthenticationSpn:TenantId was passed` というエラーが出ている場合、以下で修正できます。

**修正方法**:

アプライアンス VM の管理者 PowerShell で、`serverdiscovery.json` から SPN 情報を `appliance.json` にコピーします:

```powershell
$jsonPath = "C:\ProgramData\Microsoft Azure\Config\appliance.json"
$json = Get-Content $jsonPath -Raw | ConvertFrom-Json
$sdJson = Get-Content "C:\ProgramData\Microsoft Azure\Config\serverdiscovery.json" -Raw | ConvertFrom-Json
$json | Add-Member -NotePropertyName "AgentAuthenticationSpn" -NotePropertyValue $sdJson.AgentAuthenticationSpn -Force
$json | ConvertTo-Json -Depth 10 | Set-Content $jsonPath
Restart-Service -Name "amserverdiscoverysvc" -Force
# 確認
(Get-Content $jsonPath | ConvertFrom-Json).AgentAuthenticationSpn
```

TenantId と ApplicationId が表示されれば修正完了です。

### Azure への接続チェックが失敗する

アプライアンスから Azure への接続には、アウトバウンドインターネット（HTTPS 443）と DNS 名前解決が必要です。

- **NAT Gateway**: `snet-onprem` に NAT Gateway が付与されているか確認
- **DNS**: VNet の DNS 設定がカスタム DNS（例: オンプレ AD）の場合、アプライアンス VM の NIC に Azure DNS (`168.63.129.16`) を直接設定

  ```powershell
  az network nic update -g rg-onprem --name <NIC名> --dns-servers 168.63.129.16 -o none
  ```

### WinRM 接続エラー（Source validation failed）

アプライアンスから検出対象 VM への WinRM（ポート 5985）が通らない場合:

- 各 VM で WinRM を有効化: `winrm quickconfig -force`
- ファイアウォールで別サブネットからのアクセスが制限されている場合: `Set-NetFirewallRule -DisplayGroup "Windows Remote Management" -RemoteAddress Any`

<details>
<summary>クリーンアップ（オプション）</summary>

アセスメント完了後、アプライアンス VM が不要であれば削除できます。

```powershell
az vm delete --resource-group rg-onprem --name vm-onprem-migrate --yes
az disk delete --resource-group rg-onprem --name vm-onprem-migrate_OsDisk_1 --yes --no-wait
az network nic delete --resource-group rg-onprem --name nic-vm-onprem-migrate --no-wait
# NAT Gateway のクリーンアップ
az network vnet subnet update -g rg-onprem --vnet-name vnet-onprem -n snet-onprem --remove natGateway -o none
az network nat gateway delete -g rg-onprem -n natgw-onprem --no-wait
az network public-ip delete -g rg-onprem -n pip-natgw-onprem --no-wait
```

> 移行実行（レプリケーション）フェーズでもアプライアンスを使う場合は削除しないでください。

</details>
